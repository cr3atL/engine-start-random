# 再来一脚 · 摩托启动原型

Babylon.js 机械启动小游戏。摩托使用 Kamesh.Hamare 的 Yamaha RX100（CC BY 4.0），通过 Blender MCP 拆分打火棍、展开脚踏并适配原有动画。原车发动机局部透视、鞋和裤腿在 Blender 中维护，导出 GLB 接入游戏。主镜头在摩托侧面近景，能看见鞋、打火棍和发动机。抓住鞋向下踩，过点火位置后切入发动机内部的十格机械转盘，最后两三格慢慢停下，再切回摩托看反应。

[在线试玩](https://cr3atl.github.io/engine-start-random/) · [GitHub 仓库](https://github.com/cr3atL/engine-start-random)

## 运行

需要 Node.js 20.19+ 或 22.12+。

```sh
npm install --legacy-peer-deps
npm run dev
```

打开终端打印的 Local 地址。手机和电脑处于同一个 Wi-Fi 时，使用 Network 中实际局域网地址访问；系统防火墙需要允许该开发服务器的局域网连接。

```sh
npm test
npm run build
npm run preview
```

构建产物位于 `dist/`，可以静态托管。引擎随构建打包，模型、机械盘面、材质、字体和音效都不需要运行时外部素材或 CDN。

## GitHub Pages

推送到 `main` 后，`.github/workflows/deploy-pages.yml` 自动安装依赖、运行测试、构建并发布到 Pages。仓库 Settings → Pages 的 Source 使用 GitHub Actions。部署不需要额外保存访问令牌，使用工作流自带的短期凭据。

`vite.config.js` 在 GitHub Actions 中根据仓库名设置子路径，模型和贴图通过 `BASE_URL` 加载。本地开发默认仍为 `/`；可以设置 `PAGES_BASE=/engine-start-random/` 来验证项目 Pages 子路径。原始参考视频、临时验证输出与 Blender 自动备份不上传，当前 `.blend` 源文件和游戏 GLB 一起版本管理。

## 操作与规则

- PC 鼠标或手机手指抓住鞋向下拖。鞋底贴着脚踏，打火棍围绕转轴运动。过约 68% 行程的点火位置立即触发，不必等松手。
- 压缩段逐渐变沉，继续拖动时脚踏移动幅度变小；咬合后快速踩到底，再以阻尼弹簧回位。膝踝按固定骨段长度联动，脚底前掌保持贴合脚踏。
- 踩得越快，转盘初速度越大、圈数越多；各奖项概率按实际十格盘面分布，不会因力度绑定奖项。
- 短拖、点击、往上拖、指针取消、离开窗口都不会误触发。空格或脚踏聚焦后的 Enter 提供中等力度代踩。
- 十格包含三格火花塞、三格活塞、三格空白和一格礼盒。
- 两次火花塞才启动。第一次鞋挪开就熄火，停一拍后鞋试探着靠近，发动机又偷偷突一下，鞋受惊缩回；第二次稳定怠速。空白和卡活塞都保留点火进度。
- 活塞只会卡顿再挣脱，没有损坏、血量、失败次数或五脚限制。
- 已获得小师傅时，卡活塞会演出一次认真抢修：踩上检修踏板、双手推不动、撤手停顿、侧肩蓄力顶开、失力回晃再站稳。金色活塞仍缩短卡顿，动作和音效同步加快。
- 礼盒随机给金色活塞或原厂小师傅，再中礼盒会给另一种，两者在本局持续保留。两种都获得后再中礼盒，师傅会得到一把小油壶。
- 金色活塞缩短卡顿，成功后排气管逐渐吹成喇叭口。小师傅参与启动，成功后伸手要工钱。普通成功则震歪后视镜。所有搞怪都发生在摩托周围，发动机保持运转。
- 右上角提供声音、操作说明和重新开始。两枚火花塞图标表示点火进度，已获得的辅助只显示图标；操作提示首次踩踏后退场，笑点由动作和停顿呈现。

## 实现与验证

- `src/game.js`：独立的状态转换、奖项、礼盒和转盘运动曲线。
- `src/world.js`：侧面机械近景与发动机内部两组 3D 场景、摄像机、脚踏、活塞、礼盒和成功反应。
- `assets/blender/rx100-game.blend`：当前可编辑 Blender 源模型；`public/assets/models/rx100-game.glb` 是游戏实际加载的交换资产。
- `tools/blender/`：通过 Blender MCP 执行的建模、UV、导出与几何检查脚本。`docs/blender-workflow.md` 说明维护方式。
- `src/blender-motorcycle.js`：加载 Blender 模型，连接原有脚踏、活塞、礼盒、后视镜和排气表演挂点；将 Blender 裤腿网格沿原有膝踝解算结果变形。
- `src/modeling.js`：原有转盘及小师傅等辅助场景的几何工具；`src/crosscub.js` 为上一版车体的历史代码，已退出游戏加载路径。
- `src/performance.js`：鞋与发动机的第一次点火表演、小师傅抢修分段动作、归还控制的时点与共用音效标记。
- `src/lottery.js`：机械盘面、火花塞/活塞/礼盒图案、旧漆和划痕。
- `src/gesture.js`：拖动速度计算和有效踩踏距离。
- `src/pedal.js`：压缩阻力曲线、咬合与回弹运动、固定长度的膝踝解算。
- `src/materials.js`：哑光绿色漆、PBR 铸铝、加工钢材、ABS、橡胶、皮革和布料材质，使用随项目打包的预过滤 HDR 环境。
- `docs/model-reference.md`：官方车型与骑手参考、场景尺度和贴图来源。HDR 贴图的署名保存在 `public/assets/ATTRIBUTION.txt`。
- `src/main.js`：输入、切镜、停奖、点火进度和反应节奏。
- `src/audio.js`：Web Audio 混音、按实际过格时刻预调度的卡齿声、锁止与结果回声，以及和表演共用时点的启动、卡顿、怠速、抢修与喇叭音效。暂停、失焦、静音和重开会清理排队声音。
- `src/mechanical-sound.js`：本地合成的机械瞬态，以阻尼金属共振、低频燃烧脉冲和摩擦噪声构成，没有外部录音或音乐式中奖提示。
- `src/feedback.js`：从既有转盘曲线反算每个卡齿时刻，以及停稳后的短暂格子反光与指针回震。最后三次过格清楚分开，停奖仍保留原有 0.52 秒，不改变奖项或抽奖曲线。

转盘先快速旋转，接着用 1.75 秒走完最后约两格半，停稳 0.52 秒后切回；减速连续且不会停稳后跳奖。测试覆盖两次点火、进度保留、无损卡顿、礼盒持久化、重复输入保护、十个落点和减速曲线、拖动速度及误触过滤。

开发服务器下的 `tests/visual-check.html` 是独立的视觉验证页，可定格发动机侧面、斜视角、踩到底和踩踏斜视角，也可检查原有反应。它不进入正式构建，不改变随机结果。`assets/blender/rx100-audit.json` 保存 Blender 中的三角面交叉检查：缸体与曲轴箱、排气与曲轴箱/轮胎，以及 7 个踩踏姿态的鞋、裤腿与车体；装配法兰、轴承、鞋底踩踏等接触面单独列出。测试校验该报告与发出的 GLB 的 SHA-256 一致，并检查动画挂点、裤腿绑定姿态、UV 和三角面预算。
